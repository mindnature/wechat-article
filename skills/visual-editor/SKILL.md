# VisualEditor｜公众号视觉编辑 Skill

## 目标

把一篇已经完成结构或正文的微信公众号文章，转成“可执行的视觉编辑单”。

本 Skill 不把配图当装饰，而是把每张图视为正文的一部分。核心原则：

- 真实图优先承担“证明”。
- 生成图优先承担“解释、概念化、情绪表达”。
- 数据适合图表/信息卡，不适合只做氛围图。
- 图片数量由阅读节奏和信息功能决定，不机械规定每篇固定张数。
- 网上图片必须记录可核验图源；标注图源并不自动等于取得版权许可，优先使用官方发布、明确授权、CC/公共领域或可合理引用的素材。

## 输入

至少需要以下一种：

1. 完整文章；
2. ArticleArchitect 输出的文章结构；
3. 文章 + 已有素材包。

如有账号名称，读取 `../shared/account-profiles.md`。

## 工作流程

### Step 1｜画阅读节奏图

先按正文内容标出：

- 开头钩子区
- 关键事实区
- 数据/机制区
- 案例区
- 反转/高潮区
- 结论/行动区

判断哪些位置连续文字过长、抽象度过高、证据不足或情绪需要切换。

### Step 2｜给每个候选插图分配功能

每张图只能有一个主功能：

1. `evidence` 证据图：官方通知、政策、论文、产品页、新闻现场、原始数据截图。
2. `explain` 解释图：机制图、流程图、关系图、对比卡、知识卡。
3. `story` 故事图：人物、产品、场景、事件现场。
4. `emotion` 情绪图：抽象情绪、生活场景、隐喻画面。
5. `rhythm` 节奏图：在长文中创造视觉呼吸，但必须与上下文相关。

若一张图没有明确功能，删除。

### Step 3｜决定“真实图”还是“生成图”

使用以下判断顺序：

- 为了证明某件事发生过 → 优先真实图。
- 必须保持人物、产品、机构、页面真实性 → 真实图。
- 需要展示原始数据、政策条款、论文或平台界面 → 真实截图/图表。
- 需要解释抽象机制、流程、概念 → 生成图或自制信息图。
- 需要表达不可直接拍摄的情绪/隐喻 → 生成图。
- 如果真实图已足够清晰，不为“统一画风”强制重生成。

### Step 4｜规划封面

封面优先表达：

`主题识别 + 最强冲突/数字/人物/对象`

不要只追求“高级感”。读者在信息流里首先应该知道文章讲什么。

输出：

- 封面核心视觉
- 封面主元素
- 是否需要文字
- 若需要：短文案（尽量 4–10 字）
- 适合生成 / 适合真实图 / 混合方案
- 画面构图建议

### Step 5｜真实图片搜索单

对每张需要网上寻找的图片输出：

- 搜索目标
- 推荐搜索关键词（中英文如有必要）
- 优先来源顺序
- 最希望找到的画面
- 最低清晰度/裁切要求
- 图源记录字段

优先来源：

1. 官方网站 / 官方公众号 / 官方社媒 / 项目主页；
2. 论文、报告、原始数据发布方；
3. 企业官方媒体包 / 产品官网；
4. 权威新闻媒体；
5. 明确许可的图库或公共领域资源；
6. 其他可核验来源。

不要把搜索结果页、无来源搬运图、明显带水印盗图作为首选。

### Step 6｜生成图指令

每张生成图输出一个独立生成要求，必须包含：

- 内容主体
- 场景
- 信息功能
- 构图
- 视觉风格
- 画幅
- 是否需要留标题/文字空间
- 禁止项（错误文字、错误Logo、虚构数据、误导性新闻现场等）

默认品牌方向可采用“手绘纸张信息图 / 手绘知识卡片”，但应根据账号和文章主题调整，不机械统一。

### Step 7｜图源标注

统一格式示例：

- `图源：国家自然科学基金委员会官网`
- `图源：Kickstarter 项目页面`
- `图源：新华社`
- `图源：XXX官网，作者整理`

对于截图，尽量保留可识别的页面来源信息，同时裁掉无关内容和个人隐私。

如果许可状态不清楚，标记：`版权/授权需确认`。

## 五号差异化

- 思然日新：官方通知、政策、论文、项目指南、框架图优先。
- 思然知己：产品页面、模型能力、轻科技解释图优先。
- 思然天工：界面截图、步骤图、前后对比、工作流图优先。
- 思然经世：产品、价格、收入、用户/众筹/商业数据和模式图优先。
- 思然修远：真实社会事件 + 有叙事感的情绪/生活场景图优先。

## 禁止

- 不用AI生成“看起来像真实新闻现场”的伪证据图。
- 不为凑数量插无关图片。
- 不把“标注图源”当成版权许可的替代品。
- 不在生成图中虚构可被误认为事实的数据、官方文件或人物言论。
