# Paragraph Rhythm｜正文段落节奏

v0.7.1 是对 v0.7 的可读性补丁，不改变 Reader Contract、POV 竞争、Clarity Pass 与 BlindReview 主链。

核心原则：

> 宏观结构可以清楚，正文不能碎。

`01/02/03/04` 属于导航；正文段落属于叙述。两者不要混为一谈。

## 1. 默认段落

公众号正文默认使用完整自然段：
- 以 2–4 句完成一个小意思；
- 句长可以不均匀；
- 不要求每段一样长；
- 一个自然段里可以包含短句，但不要把每个短句单独拆成段。

## 2. 单句段落

单句段落只用于：
- 核心结论；
- 明确转折；
- 必要的情绪停顿；
- 极关键的读者提醒。

不是默认排版手段。

规则：
- 不允许连续 3 个及以上单句正文段落；
- Standard/Deep 一篇文章中，极短单句段（约 20 字以内）默认不超过 2 个；
- 极短单句段不能连续出现；
- 小标题、列表项、图注不计入正文单句段。

## 3. 禁止名词拆行制造节奏

禁止把一组本可在一句话中表达的信息拆成：

```text
算力。
数据。
场景。
融资。
```

优先写成：

```text
继续往后看，会发现政策接入的并不只是一句“鼓励”，而是一整套资源，包括算力、数据、真实应用场景、孵化、赛事和融资。
```

同样禁止：

```text
一个人。
一个问题。
几个Agent。
一个客户。
```

除非这一组短段是文章唯一一次、且确实承担核心收束功能；默认仍应合并成自然段。

## 4. 编号框架与正文

推荐：

```text
01｜文献研究：先把“搜、下、整、比”交出去

老师不需要自己在数据库、文件夹和表格之间反复切换。Agent 可以先完成检索、下载、去重、提取研究问题和方法，再把结果整理成 Literature Matrix；老师最后检查关键文献和研究缺口是否可靠。
```

不推荐：

```text
01｜文献研究

搜索。
下载。
去重。
提取。
建矩阵。
```

宏观可以碎成 01/02/03/04，微观内容必须重新合并成自然叙述。

## 5. Readability Gate

Writer 在 Clarity Pass 中额外检查 Paragraph Rhythm：
- 是否连续出现 3 个单句段；
- 是否连续出现 2 个极短段；
- 是否存在名词逐行堆叠；
- 是否为了“节奏感”人为增加滑屏距离；
- 正文是否仍以 2–4 句自然段为主。

发现问题优先合并段落，不做同义词改写。

## 6. 自动检查边界

`scripts/validate_readability.py` 会扫描 `writing.sections[*].text` 中保留的换行：
- 连续单句段；
- 极短段；
- 极短段连续堆叠；
- 单句段占比。

机器只能发现明显碎片化，不能判断所有排版美感。最终 PublisherQA 仍需结合手机端阅读体验判断。

## 最终标准

> 小标题负责导航，段落负责把话说完整。

读者应该能快速扫懂框架，也能连续读完正文，而不是每读几个字就被迫滑一次屏。
